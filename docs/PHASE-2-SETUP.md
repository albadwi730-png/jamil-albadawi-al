# JAMIL AI — Phase 2 foundation and setup

This branch adds the first persistent data/auth foundation and PWA shell. It does not yet constitute a deployed backend or a working AI generation service.

## Supabase setup

1. Create a Supabase project in the owner's account.
2. In Project Settings → API, copy the Project URL and anon/publishable key.
3. Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` in the frontend hosting environment (or local `.env`, which is ignored by Git).
4. Apply `supabase/migrations/202611190001_initial_schema.sql` using Supabase CLI or the SQL editor.
5. Configure Auth email provider, SMTP, redirect URLs, and production site URL.
6. Keep the service-role key exclusively in server-side secret storage. Never use it in `VITE_*` variables.
7. Verify the owner account by signing in with `albadawi730@gmail.com` after email confirmation. The database trigger promotes only that verified email; client metadata cannot grant OWNER.

## Security notes

- RLS is enabled on all application tables in the initial migration.
- Wallet mutations are restricted to the `service_role` through `apply_wallet_transaction`; the browser cannot credit itself.
- Storage bucket `user-assets` is private and object paths must begin with the authenticated user's UUID.
- AI job execution/status updates, payment approval, and administrative mutations must be implemented in trusted server functions before being exposed in production.
- Review the SQL migration in a staging project before applying it to any project containing production data.

## PWA and mobile

- The web manifest, SVG app icons, and service worker provide a basic installable app shell. Test installability on HTTPS after deployment.
- `capacitor.config.ts` defines the native app identity and `dist` web directory. Install Capacitor CLI/core and add Android/iOS platforms in a development environment before expecting native project files or APK/AAB output.
- No APK, AAB, or signed iOS archive is generated by this commit.
